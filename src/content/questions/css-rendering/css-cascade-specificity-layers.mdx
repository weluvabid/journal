## Short answer

The cascade compares declarations in ordered stages. Importance and origin, cascade layer order, specificity, scoping proximity where applicable, and source order determine the winner. Specificity is only one stage.

## Reason from first principles

Normal declarations in later layers win over earlier layers; important declarations reverse layer precedence. Unlayered normal styles outrank layered normal styles. This is why adding a more specific selector does not always solve a cascade-layer conflict.

## A concrete example

```css
@layer reset, components, utilities;
@layer components {
  .button {
    color: navy;
  }
}
@layer utilities {
  .text-red {
    color: crimson;
  }
}
```

## Boundary cases to reason through

Cascade layers are ordered before specificity is compared, so a low-specificity selector in a later normal layer can beat a highly specific selector in an earlier layer. Important declarations reverse layer precedence. Establish layer order once near the application entry point; otherwise independently imported styles can create surprising precedence.

## Common misconception

The cascade is not simply “the most specific selector wins.”

## Why this matters in production

Use layers to establish predictable ownership and reduce specificity escalation in large applications.
