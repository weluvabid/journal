## Short answer

The containing block depends on the positioning scheme and ancestor properties. Absolute elements are commonly positioned relative to the padding box of the nearest qualifying positioned ancestor; fixed elements are usually viewport-relative unless an ancestor establishes a fixed-position containing block.

## Reason from first principles

Transforms, filters, perspective, and some containment properties can establish containing blocks for positioned descendants. This explains why a fixed tooltip may unexpectedly move with a transformed parent.

## A concrete example

```css
.dialog-shell {
  position: relative;
}
.dialog-shell .close {
  position: absolute;
  inset: 1rem 1rem auto auto;
}
```

## Boundary cases to reason through

A transformed ancestor can become the containing block for a fixed descendant, which is a frequent source of broken viewport overlays. Absolute positioning also depends on the nearest ancestor that establishes the relevant containing block, not necessarily the visually nearest wrapper. Diagnose the containing block and clipping ancestor separately; they are different questions.

## Common misconception

`position: fixed` is not unconditionally anchored to the viewport in every containing-block context.

## Why this matters in production

Portals can escape clipping and containing-block constraints, but introduce focus, stacking, and ownership concerns.
