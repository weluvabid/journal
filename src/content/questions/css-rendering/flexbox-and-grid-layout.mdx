## Short answer

Flexbox is optimized for distributing items along one primary axis; Grid models rows and columns together. Both can solve many layouts, so choose the model that expresses the constraints most directly.

## Reason from first principles

Flex items have automatic minimum sizing that can prevent shrinking; `min-width: 0` is often necessary for overflowing content. Grid track sizing includes intrinsic contributions, and `minmax(0, 1fr)` can avoid min-content constraints.

## A concrete example

```css
.layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 18rem;
  gap: 1.5rem;
}
@media (max-width: 48rem) {
  .layout {
    grid-template-columns: 1fr;
  }
}
```

## Boundary cases to reason through

Intrinsic sizing is often the hidden cause of overflow. A flex item defaults to an automatic minimum size based on its content; setting `min-width: 0` allows it to shrink. Grid tracks can have similar min-content constraints, which is why `minmax(0, 1fr)` is useful. Test long unbreakable strings, large controls, and translated labels.

## Common misconception

Grid is not only for page-level layouts, and Flexbox is not only for tiny components.

## Why this matters in production

Model layout from content constraints, then test long text, localization, zoom, and narrow viewports.
