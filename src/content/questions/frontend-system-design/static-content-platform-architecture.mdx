## Short answer

Treat content as structured source data. Generate routes, navigation, search documents, and relationship links from the same validated model. Use build-time checks to catch broken IDs and references before deployment.

## Reason from first principles

A static site can still have dynamic client-side interactions without a backend. The hard parts are content governance, stable identifiers, URL evolution, search indexing, and build reliability—not server infrastructure.

## A concrete example

```ts
interface Entry {
  id: string;
  slug: string;
  domain: string;
  prerequisites: string[];
  related: string[];
}
```

## Boundary cases to reason through

A stable ID should survive title edits and route changes because progress and relationships depend on it. CI should validate duplicate IDs, missing references, cycles, malformed metadata, and internal links. Slugs are presentation and routing; IDs are identity. Keep redirects when a published slug changes so search engines and external references do not break.

## Common misconception

Static does not mean unstructured, and Markdown files alone do not guarantee valid content.

## Why this matters in production

Use stable IDs, schema validation, link checks, editorial templates, and PR-based review. Keep browser JavaScript proportional to actual interaction.
