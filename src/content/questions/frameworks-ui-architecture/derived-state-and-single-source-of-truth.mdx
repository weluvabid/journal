## Short answer

Store the minimal state needed to represent user intent; derive values that can be computed from it. Duplicating derived data creates multiple sources of truth that must be kept synchronized.

## Reason from first principles

If `filteredItems` is fully determined by `items` and `query`, storing it independently creates invalid combinations. Memoization is a performance optimization, not a correctness requirement; introduce it only when measurement or identity semantics justify it.

## A concrete example

```ts
const visibleItems = items.filter((item) => item.name.includes(query));
```

## Boundary cases to reason through

Effects that copy one state variable into another often create a one-render lag and ordering problems. Derive synchronously when possible. If a value is expensive, memoize based on its real dependencies; if it represents a user decision, store that decision rather than a derived projection. Async resources need explicit pending, success, and error states.

## Common misconception

“Avoid derived state” does not mean “never cache.” It means cache only with an explicit invalidation and consistency model.

## Why this matters in production

This principle reduces effect chains, stale UI, race conditions, and unnecessary state transitions.
