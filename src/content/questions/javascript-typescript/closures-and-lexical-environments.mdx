## Short answer

A closure is a function together with access to the lexical environment in which it was created. The environment remains alive while it is reachable through the closure.

## Reason from first principles

The engine does not need to preserve an entire outer stack frame. It preserves the bindings that remain reachable. Closures observe bindings, not necessarily snapshots: if a captured binding changes, later calls can observe the new value.

## A concrete example

```js
function counter() {
  let value = 0;
  return () => ++value;
}
const next = counter();
next(); // 1
next(); // 2
```

The returned function keeps the `value` binding reachable.

## Boundary cases to reason through

The distinction between a binding and its current value matters in loops and callbacks. A `let` binding is created per loop iteration, while a `var` binding is shared by the containing function. Capturing a DOM node or large cache can keep its entire reachable graph alive; remove listeners and timers when their owner is disposed.

## Common misconception

Closures do not automatically cause memory leaks. A leak occurs when something retains a closure or captured object longer than intended.

## Why this matters in production

Event listeners, timers, subscriptions, and cached callbacks can retain large object graphs. Cleanup is about removing unnecessary references, not avoiding closures.
