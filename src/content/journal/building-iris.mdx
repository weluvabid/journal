I got tired of rebuilding the same buttons, dialogs and form spacing every time a project needed a UI. Iris is the boring package I extracted so Pulse, Frontend Atlas and the journal could share primitives without sharing a brand.

The job is modest. Reusable Svelte components and a predictable base. Not a framework, not a router, not an opinion about how the app stores state. If Iris starts owning navigation, I've built the wrong thing.

Interaction behaviour comes from shadcn-svelte's primitives. I am not reimplementing dialog focus traps, popover positioning or menu keyboard maps. Those are full of edge cases and I already depend on an implementation that has them. Iris sits on top: composition, tokens, the bits that should look related across my projects.

Monochrome on purpose. Light and dark. Tokens instead of a baked-in product colour. Readable labels, visible errors, spacing that doesn't change personality per component. Tailwind where it keeps the styles in one system. Not fifty style props so every consumer can invent a new button.

The demo exists to prove install, compose, theme. If the demo gets more interesting than the library, I've started a second product by accident.

The package boundary is the product. Stable exports, honest peer deps, styles that don't reach into undocumented repo paths, a tarball that installs in an empty project. A local demo that "works on my machine" is not a release. 0.4.1 on npm was a checkpoint, not a claim that the component set is finished.

What I want to keep: small, composable, slightly dull. Don't hide the primitives. Don't force a visual identity on the next app. Success is whether another repo can take a dialog, understand the contract, and move on.
