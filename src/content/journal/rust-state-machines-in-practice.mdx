A pile of booleans will happily be `is_running` and `is_done` at once. The compiler doesn't care. An enum does, because those states are alternatives, not flags you can combine by accident.

```rust
#[derive(Debug)]
enum JobState {
    Queued,
    Running { attempt: u32 },
    Succeeded { output_id: String },
    Failed { reason: String },
}
```

Success carries an output id. Failure carries a reason. You can't build "succeeded, no output, still queued." Adding a variant is annoying on purpose. Every match that understood the old set has to look at the new one.

I don't reach for typestate unless the sequence is actually fixed. A builder that must not run until the required config exists is a decent typestate. A job that moves because an outside event arrived, or because persisted state says so, is a runtime enum. The next event isn't visible to the compiler. Pretending it is just hides the illegal state in a conversion you forget to test.

Ownership is the other half. If the transition takes `self` and returns the next state, the old value is gone. Borrow when the caller is only looking. The signature should say which of the three this is: observe, mutate, consume.

Async is that machine, generated. The future stores what has to live across an `.await`. `Pending` means not done, poll again after the waker fires. `Ready` is the output, and that poll used up the progress. `Pin` is there because the future can point into itself across the suspension. Less magic once you treat it as states plus a scheduler.

A transition I trust is: this state, this event, either a legal next state or an error with a name. Tests list the legal ones and reject the rest. If you persist it, decode is part of the machine. Bytes that parse are not a `JobState`. Old shapes, a field that doesn't belong on `Queued`, a success with no id. Reject those at the boundary.

Then stop. A value with no lifecycle doesn't need a ceremony enum. Encode the rules that are real.

```rust
fn complete(state: JobState) -> Result<JobState, JobState> {
    match state {
        JobState::Running { .. } => Ok(JobState::Succeeded {
            output_id: "report-42".into(),
        }),
        other => Err(other),
    }
}
```

Only `Running` can complete here. A real transition function would carry the output and failure reason from the operation rather than hard-code an id.
