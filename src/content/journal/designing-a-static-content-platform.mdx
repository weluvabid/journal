I write articles and project notes on this site. I publish by editing files in the repo. Adding a database, admin panel and content API would add a lot of extra complexity to the publishing process.

Astro generates the pages. The MDX and Markdown files live in the repo. The collection schema validates the frontmatter, and invalid fields make the build fail in CI. Git is used for review. It's pretty basic: the changes are diffs, and I can revert them if needed. There are no migrations. The downside is that publishing means building and deploying. There's no live editing, but I don't miss it.

The browser gets HTML. Svelte hydrates the header controls, search, keyboard shortcuts and the list that loads more entries as you scroll. The article content itself stays static.

Search uses a JSON index generated with the site. The header loads it during hydration, and the dialog ranks results locally. The index includes each article's title, summary, tags, search terms, route and normalized searchable text. This lets search rank a query without loading each page.

The first page of the journal is useful on its own. As you scroll, more items load. I could generate a single page for the archive, but that would send the entire archive to everyone.

Even with static pages, there's still UI work: focus, keyboard behaviour and saving the theme. I hit a painting issue in mobile Safari. The fix was specific to that rendering path. Adding an animation across the whole site to cover all bases would have been a sign that I hadn't understood the problem.

The typography is simple: monochrome with subtle accents. There's no layout competing with the note.

There are currently no user accounts or user-specific data in the publishing process. If the site grows to need either, I'll introduce a service to handle it.
