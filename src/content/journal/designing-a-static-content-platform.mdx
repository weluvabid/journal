This site is articles and project notes. Visitors read them. I publish by changing a file. I didn't want a database, an admin, and a content API in front of that.

Astro builds the pages. MDX and Markdown live in the repo. The collection schema fails the build if frontmatter is wrong — a missing field is a CI problem, not a surprise in production. Git is the review tool. Diffs, revert, no migration. The cost is that "publish" means build and deploy. There is no live editor, and I don't miss it for this.

The browser gets HTML. Svelte hydrates where something is actually interactive: search, theme, keyboard shortcuts, the list that grows as you scroll. Not the article body.

Search is a JSON index generated with the site. The dialog fetches it when you open search, then ranks locally. No search box that round-trips to a server for a corpus this size. The index is titles, summaries, tags, search terms, routes. Not the full article text glued into the first paint.

The first page of the journal is useful by itself. More entries load as you go. Generating one giant archive page because it was easy would just ship the archive to everyone.

Static does not mean the UI is free. Focus, keyboard, theme persistence, small screens — still work. I hit a mobile Safari paint bug that didn't show up on desktop. The fix stayed on that rendering path. A site-wide animation "just in case" would have been me not understanding the bug.

Type is the product. Monochrome, small accents, no layout competing with the note.

If I later need accounts, per-user state, or content that changes between deploys, that's a service. It isn't a reason to pretend this site already has one.
