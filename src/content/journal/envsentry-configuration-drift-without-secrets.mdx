A line diff will tell you a config file changed. It will not tell you a key is missing, duplicated, or shaped wrong. EnvSentry compares dotenv, JSON and TOML after they're the same kind of document. The comparison code never learns which parser ran. The report never prints the values it compared.

Three crates, dependencies only downhill:

- `envsentry-core` — paths, values, documents, diagnostics, sensitivity. No files, no terminal.
- `envsentry-parsers` — dotenv, JSON, TOML into that model.
- `envsentry-cli` — args, read the files, pick a parser from the name, render, exit code.

CLI reads UTF-8, gets a `ConfigDocument`, asks core to compare, prints diagnostics. A new format shouldn't mean new branches inside the differ.

Entries live in a `Vec`, not a map. Duplicates are a finding. A map would throw the evidence away before the differ ran. Containers get an entry at their own path *and* entries for children, so an empty object is still a structure, and an object isn't the same as a scalar sitting on that path. Array indexes are path segments.

Keys can contain dots, brackets, backslashes, control characters. Display escaping exists so the path you print isn't a second, ambiguous syntax. Control characters stay on one line. That's also so a path can't poke the terminal.

Dotenv parse does not touch the process environment, and repeated assignments survive. JSON must be an object at the root, and repeated keys are kept, including nested ones. TOML duplicates die in the TOML parser. I don't reimplement that.

Core indexes paths with a `BTreeMap`. Missing, unexpected, repeated. If a path shows up once on each side, kinds are compared first, then the stored text. `01` and `1` are different. I'm not in the business of deciding which numeric spellings are "the same." Empty and whitespace-only values are their own check, not a side effect of value compare.

Diagnostics sort by path, code, severity, source, location. Same inputs, same bytes out. That's what makes a CI snapshot worth having.

Missing and duplicate keys are errors. Unexpected keys, empty values, value and type mismatches are warnings. `--strict` makes warnings fail the process and does not relabel them as errors. `check --schema` ignores value and type differences and still reports structure and empties.

| Finding | Default severity | `--strict` effect |
| --- | --- | --- |
| Missing key | Error | Still fails. |
| Duplicate key | Error | Still fails. |
| Unexpected key | Warning | Fails policy; remains a warning. |
| Empty value | Warning | Fails policy; remains a warning. |
| Value or type mismatch | Warning | Fails policy; remains a warning. |

Exit `0` policy passed, `1` findings failed the policy, `2` the tool failed (bad args, format, I/O, parse, report write). Scripts need that split. A usage error is not drift.

Values exist in memory. They have to, or you can't know they differ. They do not leave in text or JSON reports; diagnostics do not include old values or new values. No old value, no new value, no preview. `ConfigValue`'s `Debug` redacts the raw field. Parser errors don't echo input.

There's a `SensitivityPolicy` for names like `PASSWORD`, `SECRET`, `TOKEN`, `API_KEY`, `DATABASE_URL`, `PRIVATE_KEY`, case-insensitive, with `*` patterns. Public patterns win over sensitive ones. An explicit classification on the entry wins over the name. Array indexes are stripped before the dotted name is classified, so `services[0].api_token` is judged as `SERVICES.API_TOKEN`.

The CLI currently ignores all of that and prints no values anyway. Parsers mark entries `Unknown`. Classification is in core for later. The invariant I actually ship is simpler: diagnostics don't contain compared values. Don't describe the policy as if the CLI were redacting selectively. It isn't.

Files are fully in memory while this runs. Shell history, your editor, `ps`, anything else that can see the file — not this tool's problem, and not solved by a clean report.

Not done, and I don't want it implied: line/column from the built-in parsers (the model has the fields; the parsers don't fill them), semantic comparison, streaming big files. Synchronous, whole file, kind plus stored text.

```text
ERROR MISSING_KEY  DATABASE_URL  source=.env.example
ERROR DUPLICATE_KEY  API_TOKEN  source=.env
WARNING VALUE_MISMATCH  LOG_LEVEL
```

The report identifies paths and findings, not old or new values. Built-in parsers currently mark sensitivity as `Unknown`; the CLI omits compared values unconditionally. This is not selective secret detection.
