A screenshot and a row of badges tell me you can run a toolchain. They don't tell me you understand the system. I want the problem, the constraint you refused to break, what the thing actually does, and something I can check.

Cachewise isn't "a TypeScript cache." It's the argument that recency, frequency, rebuild cost and size shouldn't be collapsed into LRU. TinyLSM isn't a map with extra steps. It's publish-before-clear, tombstones, newest-wins, and a merge. Needle isn't a Brainfuck costume. It's source maps and reverse steps that don't snapshot the whole tape. If the project page can't say that in a few lines, the project page is a brochure.

Limits belong on the page. TinyLSM has no WAL. Cachewise's byte budget is the estimator's opinion, not the heap. WordWeave is not encryption. A project that admits where it stops is easier to trust than one that says production-ready and hopes you don't look.

"Fast" and "secure" are conclusions. The evidence is the workload, the metric, the threat model, the test that fails when the invariant breaks. A README that only repeats the marketing paragraph makes me clone the repo and reverse the setup. That's a documentation bug.

Journal entries shouldn't be the README pasted into a longer file. The project page is the map. A note should take one decision and stay there.

I care more about whether a reviewer can go claim → code → test than about how many repos are on the list. If I can't point at the artefact, I shouldn't have written the sentence.
