`JSON.stringify` works well for tree-shaped values. `undefined` disappears, `BigInt` throws, cycles throw, and two fields that point to the same object decode as separate objects. JSON+ is a versioned JSON format for a bounded set of JavaScript values. It preserves cycles and shared identity. Functions, closures, symbols, DOM nodes, weak collections and arbitrary classes sit outside the format.

The important part is object identity. If `first` and `second` point at the same object, the graph has one node with two incoming edges. If an object points back to itself, that edge forms a cycle. The wire format needs to preserve both relationships.

Envelope is small: `format`, `version`, `root`, `nodes`. Primitives go inline or as explicit tags (`undefined`, `NaN`, infinities, `-0`, `BigInt` as canonical decimal). The first time the encoder sees a referenceable object it records the identity _before_ walking children. Later hits reuse `{ "$ref": n }`. That's how cycles fall out without a special recursive case.

The node table doubles as the work queue. A cursor walks it while newly discovered objects are appended, so encoding stays iterative without another traversal structure.

Properties, array slots and Map entries are flat alternating buffers. A tuple per pair would be a lot of garbage for no information. Arrays store indexes, so a hole stays a hole and doesn't become an explicit `undefined`.

Decode uses separate phases:

```text
parse → schema, refs, reachability, limits
      → allocate objects and buffers
      → wire edges
      → resolve root
```

Allocating nodes before wiring their edges makes forward references and cycles straightforward. The decoder validates the document first, then builds the graph. Unknown tags, duplicate keys, bad references, uneven pair buffers, misaligned typed-array views, non-canonical Base64, unreachable nodes and oversized payloads produce stable `JSONPlusError` codes. Duplicate JSON keys are checked in the original text because `JSON.parse` would otherwise discard earlier values.

Supported: ordinary objects and null-prototype objects, sparse arrays, `Date`, `RegExp` (including `lastIndex` as a graph edge), `Map` and `Set` in insertion order, `ArrayBuffer`, typed arrays, `DataView`. Views share backing-buffer identity. Buffers are allocated before views so the offset is real.

| Value family       | Version 1 support                                                  | Preserved contract                                        |
| ------------------ | ------------------------------------------------------------------ | --------------------------------------------------------- |
| Objects and arrays | Ordinary and null-prototype objects; sparse arrays                 | Graph identity, cycles and array holes.                   |
| Built-ins          | `Date`, `RegExp`, `Map`, `Set`                                     | Map/Set insertion order; RegExp `lastIndex`.              |
| Binary data        | `ArrayBuffer`, typed arrays, `DataView`                            | Shared backing-buffer identity, offsets and view lengths. |
| Unsupported values | Functions, symbols, DOM nodes, weak collections, arbitrary classes | Rejected rather than silently flattened.                  |

Encoding never invokes getters. Restored data properties are writable and configurable. The format preserves ordinary and null prototypes. Restored data properties are writable and configurable; property descriptors, extensibility and custom prototype chains are not serialized. Proxies are excluded because reflection can run their traps. Resizable buffers and `SharedArrayBuffer` are also outside the supported set.

The decoder validates untrusted documents against limits for nodes, edges, binary bytes, strings, collections and input/output length. Exceeding one returns `RESOURCE_LIMIT_EXCEEDED`. These limits bound decoder work; actual memory use also depends on the values being reconstructed.

The encoder writes the supported graph format, and the decoder checks the document against that format before rebuilding it. Version 1 is the only schema currently supported. A schema change gets a new version so old documents keep their original meaning.

```ts
const shared = { id: 1 };
const input = { first: shared, second: shared };
input.self = input;

const output = decode(encode(input));
output.first === output.second; // true
output.self === output; // true
```

The two properties still point at one object, and the self-edge still points back to the root.
