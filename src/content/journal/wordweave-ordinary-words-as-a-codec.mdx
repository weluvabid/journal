A filter that turns a message into a row of marks is an annoying constraint. It is not a cryptography problem. WordWeave is the experiment: selected terms become ordinary four-word phrases, and the punctuation, whitespace, and casing around them stay. Same vocabulary, you can put the terms back. That's reversible encoding. The vocabulary is public. If you needed a secret, this is the wrong shape, and "it looks like normal words" doesn't change that.

The budget is the phrase space. Each of four positions picks from 64 words.

`64⁴ = 16,777,216`

Six bits a position, 24 if you pretend the picks are uniform and independent. The fourth word is the point, not decoration. Three positions is `64³ = 262,144`. Four is 64 times that. Drop 64 reserved phrases into the three-word space and they take a much fatter fraction than the same 64 inside four-word phrases. Lower reserved fraction by 64. That's the model of the space, not a claim about English. Real words aren't uniform, positions in actual sentences aren't independent, and which words I picked changes the odds. Combinatorics sizes the toy. A corpus says whether this vocabulary survives text.

The scanner walks documents separately, so a phrase can't get assembled across a file boundary. The checked-in corpus is 135 documents and 643,164 tokens. Technical docs, literature, conversation samples. The scan on record found zero reserved-phrase collisions in that set.

Zero is not "impossible." It's "not in these documents, with this token mix." When one shows up, `findCodewordCollisions` reports the phrase and an offset in JavaScript UTF-16 code units. The unit matters because decode is exact. A reserved phrase *is* encoded content. So `decode(encode(text)) === text` only when the input didn't already contain one. That's the footgun. The round trip is defined that way. It isn't a bug you patch by being clever at the edges.

```ts
import { decode, encode, findCodewordCollisions } from 'wordweave';

const encoded = encode('A selected source term, please.');
const original = decode(encoded);
const collisions = findCodewordCollisions('ordinary text to inspect');
```

`VOCABULARY_VERSION` is the protocol. Change a mapping and an old phrase means something else, or nothing. Decode with the version you encoded with. There's no compatibility layer hiding in the words.

The README records a stretch of trying this directly in a platform chat without hitting a block. That's a note about that attempt. Not a promise about the filter, the moderators, or next week. A phrase can pass today and fail tomorrow. Trying to get around a platform's rules can also just be against the rules, however readable the sentence is. Don't put a secret in it. Don't call it encryption, authentication, or a bypass.

*Example I'd add:* one sentence, the four-word swap with the comma still there, and a second input that already contains a reserved phrase so the round-trip caveat isn't only a sentence.
