If keyboard focus gets stuck, the page isn't done. In Frontend Atlas, the header, landmarks, dialogs and focus order have to work together. A menu can look finished and still leave the keyboard user stranded.

Frontend Atlas needed a reading UI that stayed predictable on a narrow screen, with a keyboard, or with a dialog open over the article.

The page starts with semantic HTML: a primary navigation landmark, a main landmark, headings in order and a skip link past the header. Links take you somewhere; buttons do something. A clickable `div` means rebuilding keyboard behaviour that a native element already gives you.

Native controls already handle keyboard activation. A custom menu or dialog needs the rest of the interaction worked out too: where focus goes when it opens, what Escape does, where focus returns, and how Tab moves through it. Miss one and the interaction falls apart.

`open: boolean` doesn't describe the whole responsive menu. The trigger, visible links and current focus all matter. If the user picks a destination or the layout collapses, the menu can unmount while focus is still inside it. Move focus somewhere that remains in the page. A dialog follows the same rule: focus enters when it opens and returns to its trigger when it closes, as long as that trigger still exists.

Sticky headers hide fragment targets. The heading is "reached" and sitting under the bar. `scroll-margin-top` fixes that without a scroll listener. Hover-only actions disappear without a pointer. Focus rings have to stay visible in both themes. If the only signal is an animation, `prefers-reduced-motion` deletes your UI.

Visual review catches alignment problems; keyboard and screen-reader testing catch interaction failures. Tab through the page, activate every control, open and dismiss dialogs, resize with the navigation open, and follow a fragment beneath the sticky header. Automated checks find missing accessible names. Manual testing catches focus being returned to a control that no longer exists.

Put focus behaviour in the component contract. Otherwise every page has to work it out again, and the details will drift.

```html
<a class="skip-link" href="#main">Skip to content</a>
<main id="main">
  <h2 id="keyboard-contract">Keyboard contract</h2>
</main>
```

```css
#keyboard-contract {
  scroll-margin-top: 6rem;
}
```

Set the offset to the actual sticky-header height.
