If keyboard focus gets stuck, the page isn't done. Accessibility here isn't a last coat of paint on a finished shell. The header, landmarks, dialogs and focus order are one system. Style them in isolation and you get a menu that looks correct and strands the caret.

Frontend Atlas didn't need a clever application chrome. It needed a small reading UI that stayed predictable when the viewport changed, when there was no pointer, and when a dialog sat on top of the article.

Before any script runs, the document should already have a map: one primary navigation landmark, a main landmark, headings in an order that matches the page, a skip link past the repeated header. Links go somewhere. Buttons do something. A clickable `div` that imitates both is a second interaction model, and you will maintain it by hand forever.

Native controls already know how to activate from the keyboard. Custom menus and dialogs are allowed when the product actually needs them. Then you own the whole contract: open, close, where focus lands, Escape, where focus returns, and a tab sequence that still makes sense. Owning half of that is worse than using the primitive.

`open: boolean` is not the state of a responsive menu. There's a trigger, the links that exist in this viewport, and a focus location. If the menu closes because the user picked a destination or the layout collapsed, focus cannot remain on a node that just unmounted. Dialog opens, focus moves inside. Dialog closes, focus returns to the control that opened it, if that control is still there.

Sticky headers hide fragment targets. The heading is "reached" and sitting under the bar. `scroll-margin-top` fixes that without a scroll listener. Hover-only actions disappear without a pointer. Focus rings have to stay visible in both themes. If the only signal is an animation, `prefers-reduced-motion` deletes your UI.

A screenshot proves alignment. It does not prove a keyboard path. Tab the page. Activate links and buttons without a mouse. Open and dismiss dialogs. Resize while the nav is open. Follow a fragment under the sticky header. Listen to one page in a screen reader. Automated checks catch missing names. They will not catch focus returned to a button that is gone.

If focus behaviour isn't part of the component contract, every page rediscovers it, and one of them gets it wrong.

```html
<a class="skip-link" href="#main">Skip to content</a>
<main id="main">
  <h2 id="keyboard-contract">Keyboard contract</h2>
</main>
```

```css
#keyboard-contract { scroll-margin-top: 6rem; }
```

The offset needs to match the actual sticky header, not a magic number copied from another layout.
