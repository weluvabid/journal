A web page contains more than the article: navigation, ads, hidden helper text and framework UI all share the same tree. Copying it as Markdown starts with finding the content. Formatting is the easy half.

Copy 2 Markdown handles page, selection and link actions locally in Chrome. Turndown handles the HTML-to-Markdown conversion; the harder work is keeping page access, extraction and clipboard writing in their own places. Page access starts with a user action, and the clipboard write happens in an extension-owned document.

Popup, context menu, or shortcut. The MV3 service worker checks the URL, injects the bundled content script if it isn't there yet, sends a typed message. The popup uses that same path. There isn't a second extractor hiding in the popup.

Page and selection return HTML. Conversion turns the fragment into Markdown. An offscreen document, owned by the extension, writes the clipboard. Link copy can be built in the service worker. No DOM walk required if you only wanted the URL.

```text
action → worker → extract HTML → markdown → offscreen clipboard
```

The extractor works with the live page. The converter takes HTML and a base URL. Clipboard code writes from the extension document. Keeping those jobs separate stops the content script from turning into a junk drawer.

Page copy clones the document and tries Readability first. It works well on articles, while documentation sites and app UIs often need the fallback. When Readability returns too little text, the extractor checks `main`, then `article`, then `[role="main"]`, and finally the cleaned body. It copies the selected content root rather than serializing the whole page.

Filtering has separate rules for:

- structural: scripts, styles, templates, embeds, forms, native controls
- semantic: toolbars, menus, tablists, tooltips
- framework: a short list of known UI patterns

Framework rules target known UI patterns rather than removing every element with a familiar class. Documentation sites use the same component libraries for content and controls, so broad selectors would delete useful material. Keeping these rules separate makes them easier to inspect.

Readability runs on a detached clone and cannot see computed styles. Before parsing, the extractor compares the live page with the clone and removes elements that match the hidden-content checks. Clipping, absolute positioning, a 1px box or a utility class can also be used for visible content, so the extractor checks the combined visibility and layout pattern.

Selection copy has its own path: it clones the selected ranges instead of running page extraction. If the live selection has disappeared but the action still carries the selected text, the extension inserts that text directly. An empty selection returns an error instead of writing a blank clipboard.

Extracted HTML caps at 5 MB. Thin pages fail visibly.

Conversion is Turndown plus the GFM plugin: headings, emphasis, links, images, nested lists, tasks, quotes, fences, rules, tables. Extra rules for strikethrough, lazy image `src`, language hints, fence length, table pipes, whitespace. Relative URLs resolve against the page. Links allow `http:`, `https:`, `mailto:`, `tel:`. Images allow `http:` and `https:` only. Credentials in the URL get dropped. Remote images are not fetched. The Markdown keeps a destination, not a blob.

The converter takes an HTML fragment and a base URL. It has no Chrome API dependency, so HTML edge cases can run as unit tests. Playwright exercises the built extension for the parts that touch the browser.

The extension requests `activeTab`, `scripting`, `clipboardWrite`, `contextMenus` and `offscreen`. It has no persistent host permission, account system, backend or analytics service. Copied content stays in the browser, and restricted URLs return a visible error.
